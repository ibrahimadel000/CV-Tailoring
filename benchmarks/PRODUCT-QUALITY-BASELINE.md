# Active-path product-quality baseline

This is an offline diagnostic using entirely fictional profiles and hand-authored responses. It exercises `prepareNaturalComposition`, the single-draft request preparation, and `compileNaturalComposition`. It does not call a model or establish what a model would produce. It complements the existing resume-composer benchmark, which exercises a different composition path.

Run from the repository root after `npm ci --ignore-scripts --no-audit --no-fund`:

```sh
node --test tests/active-quality-baseline.test.cjs tests/skill-grouping-trace-baseline.test.cjs
node scripts/product-quality-baseline.cjs > quality-baseline.json
```

The report includes source facts, the fictional job, proposed and retained text, review notes and request hashes. Compare each case manually: citation, matching words and successful compilation do not prove factual support, attribution or useful writing. The hash identifies the prompt/request representation; it does not evaluate quality. Fixtures labeled faithful or risky express the author's intended comparison, not a semantic judgment by the script.

## Appended-wording review increment

A narrow local signal now asks the user to compare a surviving experience/project bullet with its original when the bullet starts with a single cited passage (four or more word/number tokens) and appends a token absent from that passage. It compares literal normalized tokens; it never modifies or rejects the bullet, never judges truth, and excludes multi-source synthesis. The note is recorded only when the line survives later restoration, persists with the copy, and is not exported in the PDF. Users must review and edit the copy; the flagged wording remains in the resume and will appear in the PDF unless changed.

Re-running the same 24 fictional cases after this change: all six copies and six intended faithful rewrites still remained without notes; all six obvious-risk cases were restored with notes; and the five subtle-detail examples previously retained without notes now remain with a review note. The sixth subtle case was already restored. This is a small development set, not an estimate of general effectiveness. A separate small set probes other English, French and Arabic literal examples; it is not an independently reviewed validation set.

Limitations: the signal misses inserted details, paraphrased prefixes, short source passages, multi-citation lines, many phrases in unspaced scripts and other unsupported changes. Conversely, harmless appended wording can receive a note, and a missing note does not imply correctness. No model, data contract, retry policy or factual blocking rule changed. Prioritize a broader, independently reviewed evaluation and more actionable claim-by-claim comparison before making stronger safety claims.

## Making review actionable

On a tailored copy with notes and an available source, the notes offer **Compare experience and projects**. It switches to the tailoring pane, opens the live experience/project comparison and focuses its heading, including on mobile. The comparison now labels text without an exact counterpart on both sides. Entry matching still uses unique native IDs; it does not guess which bullet corresponds to which. These labels are literal and presence-based, not proof that a claim is supported or missing. Both resumes may have been edited since tailoring. If the source is no longer available, the shortcut is omitted rather than displaying a false comparison. The user can edit the tailored copy in the regular editor.


## Mobile comparison space

On a smaller screen, opening the experience/project comparison temporarily hides the idle tailoring footer, leaving more space for review. Opening from a note also collapses the note, which can otherwise consume most of a short screen; it remains available to reopen. Closing the comparison or its parent restores the complete footer and unchanged sending/privacy disclosures. The footer and cancellation remain available throughout an in-flight request. Desktop retains the footer while comparing. The comparison still uses current source/copy state, not a generation-time snapshot, and does not judge factual accuracy.

## Current entry metadata review

The current comparison previously omitted experience location and dates and project links, even though either resume may have been edited after tailoring. A fictional offline browser regression reproduces this blind spot by changing the saved copy independently of its source. The comparison now displays labeled experience title, organization, location, start/end dates and overview, and project name, role and link on both sides. Empty fields are labeled “Not provided”; values are shown as text, not verified or automatically judged, and the view does not edit either resume. Bullet labels remain exact-text, entry-local comparisons only. This exposes current metadata for human review; it is not a generation-time audit and does not cover other sections.

## Conservative pagination experiment

A fictional coordinator CV with 15 short work bullets, six education entries and 12 certifications produced three A4 pages under automatic whole-section grouping. Splitting education into groups of three on each page yielded two pages with a continued heading, without changing content, font size or spacing. The app now tests a measured alternate layout only for three-or-more-page documents with eligible short multi-entry sections and no explicit layout choices. It uses the alternate only if it saves pages, continuation points stabilize, and a newly split previously intact section has at least two entry starts on each page. Missing measurements, unstable headings, failed alternate rendering or no page saving fall back to the original layout. Manual section and entry choices remain untouched. The PDF preview and export share the selected render.

This deliberately narrow optimization may take extra PDF renders and does not guarantee ideal pagination or solve every mostly empty last page. In particular, a two-page document with a short final certification section is unchanged; splitting that section would not by itself remove a page and may create an orphan. Tested PDF text and page bounds were checked for fictional examples; visual inspection and finite tests do not prove that every layout is free of clipping or orphaned content. Non-Latin PDF limitations remain unchanged.

### Review access for changed entries

The relationship probes show that an unsafe paraphrase can survive without a local note. A changed experience/project entry now receives one neutral, dismissible review reminder when there are no existing content notes, with a direct link to the current source-versus-copy comparison. This is deliberately based on generation-time change metadata, not a semantic risk classifier: both a faithful paraphrase and an unsafe one receive the same reminder. Reordering alone does not trigger it; the comparison may reflect later edits, and an unavailable source cannot be compared. The reminder does not block export, alter the copy, prove factual accuracy, or repair the unresolved guard blind spot. Offline browser cases exercise a fictional relationship change, a faithful rewrite, reload, small-screen access, a missing source, unchanged original and PDF exclusion of the reminder. ### Source-wording mode, summary review and fallback correction

An optional **Keep source wording** control now keeps the selected source's summary and all work/project entry text and metadata in a separate copy. Only surviving, unambiguous single-bullet references within the same entry may suggest bullet order; every remaining source bullet is appended in its original relative order. Multi-source, duplicate, missing, overview and unknown references cannot prioritize a bullet. The AI may still select, omit or regroup existing skills; users must review skill selection and the emphasis of reordered bullets. Neither the source claims nor the ordering are factually verified. This deliberately trades rewriting freedom for preservation and does not improve or validate the default generative mode. An unchanged result does not create a copy. Locks remain respected. The mode runs the ordinary response validation first and fails rather than saving if it cannot safely project the result. A structural preflight rejects source projections that exceed existing draft limits (including more than 40 nonempty bullets in an entry) before any provider request; it does not check factual meaning.

Summary-only wording changes now receive a neutral review reminder too, including a direct comparison of the **current** source and copy. Notes offer the same summary shortcut when relevant. It is not a generation-time snapshot, a claim-level evidence map, or factual verification. Both summary and work/project comparisons remain available for combined edits, and the mobile comparison temporarily clears space without hiding cancellation during a request.

Google documents that `gemini-3.5-flash` is deprecated and routed to `gemini-3.6-flash` ([model documentation](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash)). The redundant alias was removed from model selection and automatic fallback. The default development adapter now attempts at most 3.8 Flash → 3.6 Flash → 3.5 Flash-Lite on eligible transient responses or output limits; choosing a fallback model changes the order and maximum as disclosed in the UI. Other safety stops, time limits and retry guidance are unchanged. The request display now says **Last requested model** rather than claiming the requested identifier establishes Google's actual serving version. This reduces duplicate effective fallback attempts; it does not prove the models are available or solve a provider outage. Earlier 503s were obtained in intentionally single-request local tests and did not test the app's fallback. No new live model request was made in these changes.

An independent read-only adversarial review also found examples of uncited meaning loss when a paraphrase cites multiple source bullets, summary-only actor reversals without claim-specific warnings, and legitimate paraphrases rejected by literal guard rules. These remain risks in the generative mode. A meaningful release-quality evaluation still requires a preregistered, separately authored and independently reviewed holdout, including supported and unsupported examples, multi-source omissions, language and profession strata, and separate false-acceptance and false-rejection measures. Mocked results and hand-authored development probes cannot establish live model quality.

Both new source-mode browser tests also passed again on the final code. The final build passed with the existing dependency `eval` and large-chunk warnings. ## Stalled tailoring: transport deadline and cleanup (13 November 2026)

A user reported an actual app request still tailoring after more than eight minutes; the request phase, number of attempts, browser state and actual cause are not yet known. On the preceding committed code, synthetic offline tests reproduced a separate plausible failure: aborting the five-minute transport timer did not settle a fetch or response-body operation that ignored the signal. An independent Chromium reproduction also showed the busy state remain active for a stalled synthetic 429 body. This does not establish what happened in the live test.

The adapter now independently settles its asynchronous waits on abort, checks elapsed wall time when execution resumes, prevents late responses from triggering further fallback or creating a copy, and best-effort cancels unused late response bodies. Non-transient error diagnostics have a 1.5-second bounded stream read, with best-effort non-blocking cancellation and lock release; unavailable diagnostics remain generic. Timeout and cancellation messages are kept visible near the control, including while comparing on a small screen. The cancellation message warns the provider may still have processed or charged the request. Retry eligibility, maximum fallback attempts and the five-minute shared transport budget are not expanded. No AI requests were made in these offline checks.

Limitations: the timer covers transport, not synchronous preparation and compilation. Browser suspension or a blocked main thread can delay execution and UI updates; a late response is rejected once execution resumes. Successful response envelopes are still read via `response.json()` before their contents are size-checked, and stalled or oversized response processing warrants further hardening. Cancellation cannot guarantee provider-side termination or prevent charges. Synthetic uncooperative streams are robustness tests, not evidence of the live cause, model availability, or quality. Do not retry the user's live test without fresh, explicit request-budget approval; ask for a screenshot and whether the page responded after cancellation. The old local checkout will not automatically receive this fix.

A comparison of a user-provided original and exported copy revealed that an education status present in a header could remain separately in editable Imported details instead of appearing with the structured Education degree. They also show a sparse two-page layout; they do not establish the precise layout cause. No real CV, job text, personal details or output was copied into the repository.

Fictional regression cases now cover a narrowly recognized parenthesized header-only `in progress` qualifier. When a degree base and full institution match one structured entry, the original header is retained and a review notice asks the user to compare it with Education. It does not transfer the status or establish identity or facts. Detection is limited to an English form and up to three contiguous extracted lines; descriptions and other formats remain ambiguous. Existing saved profiles are not automatically updated. Wrapped or separately adjacent header lines are no longer silently deduplicated even when their joined text matches Education, because DOCX paragraph and physical-line provenance is unavailable after extraction. This can leave genuine duplicates for manual review. A single-line match is suppressed only at a boundary with one matching identity and no description; degree matching retains plus and hash symbols. This is still a narrow heuristic, not proof of identity.

The parser retains ambiguous wrapped degree qualifiers as editable content rather than placing certain recognized qualifiers in the institution field. It avoids treating recognized degree headers and short continuations as names or headlines; a potential headline within such a continuation is retained and receives a review notice. A real headline in that ambiguous location can require manual correction. Coverage is limited, and other formats or languages can still be misclassified. These changes do not fix the sparse two-page layout or establish that the generator produced a better summary. Compare source, provider proposal, local checks and output in a separate fictional investigation, and do not infer backend job experience from a skill list. ## Source-wording and citation-review increment

Keep source wording now preserves native summary, experience and project wording and bullet order by default. Optional AI-suggested reordering must be enabled explicitly; a small set of dependency words blocks some reorderings, not all. Skills can still be selected or regrouped; a user can add an omitted skill from the current source with its category and qualification. Current-source comparisons are not historical snapshots.

Compound skills are no longer automatically restored solely because part of their label occurs in a job. Some unique partial matches are offered as review suggestions; incomplete or ambiguous matches can be missed, so the current-source list remains important. A full-label occurrence can still be unrelated, optional or misleading, and even the existing English negation checks cannot understand all job context. Neither these safeguards nor source citations prove relevance or facts.

For normal AI rewriting, surviving multi-source entry passages and summary sentences now receive a comparison prompt. It does not establish whether any individual contribution was covered and does not force omitted material into the copy. Conservative restoration of overlapping or untraceable entries may still erase useful edits. Guard checks can still reject a valid paraphrase or retain unsupported meaning; real-provider quality, including the original-versus-tailored case discussed with the user, remains unverified by offline fictional tests. No private user content is included here.
