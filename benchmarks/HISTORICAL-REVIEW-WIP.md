# Historical review prototype — work in progress

**Do not merge, deploy, or use with important resume data.** This branch is a research prototype, not a release. See the current Notion product-quality handoff for context.

## Intent and scope

The prototype preserves an optional local comparison of source and final compiled summary, experience, and projects at generation time. It shows both sides independently; it does not prove attribution, meaning, or factual accuracy, and it does not change the model or semantic guards. The snapshot can retain sensitive professional text. Contact/link detection is incomplete. Project link fields are excluded; overly large or some detected link/contact-bearing snapshots are skipped rather than truncated.

## WIP storage follow-on — independent review required

- An IndexedDB version-2 upgrade creates `cv-tailor-canonical-v1` and copies the three legacy workspace values into one revisioned record in the same upgrade transaction. The entire `keyval` store, including unrelated keys and the old revision, is retained untouched. An abort rolls back the schema and copy. New writers use a transactional revision compare-and-swap and retain losing edits only in the open tab.
- A connection left open by an older version can block the upgrade. The waiting screen instructs the user to save/copy that tab's work before closing it; it proceeds when the blocker closes. A later database version change invalidates the new connection without reloading or replacing the current tab's edits.
- Old clients using idb-keyval's versionless open can reopen and write the retained legacy store separately. Those changes are **not synchronized or reconciled** into the canonical store; users must reconcile manually. Clients explicitly opening version 1 fail with `VersionError` after upgrade. A noncooperating writer to the canonical record can bypass the revision protocol. No cleanup mechanism is implemented.
- **Deleting a comparison in the canonical store is not global secure erasure.** The legacy store remains, potentially with the comparison and other sensitive data; old tabs, browser storage internals, other copies and backups can also retain it. Removing one copy does not remove other review notes, metadata or copies.
- Structured-clone values are migrated by IndexedDB rather than JSON. Map, Set, cycles and aliases inside supported graphs are no longer compared by raw deep equality. A conservative topology guard rejects some broken shared relationships. For shared graphs it also rejects structural removals (except the requested snapshot), array size changes and object arrays without stable unique IDs; this can block legitimate edits. These guards are not proof of safety for every possible graph or UI transformation; independent review and broader adversarial tests are release blockers. Unsupported graph types such as Blob fail visibly on load/save and leave the stored copies intact. Supported structured clone does not imply every application action preserves arbitrary future metadata.
- Recovery is not an automatic restore: the JSON download is offered on save errors only after a conservative tree-shaped JSON check. Maps, cycles, shared references, undefined and other non-JSON values fail visibly instead of producing a lossy backup. The tab can still be lost on browser shutdown; manual reconciliation is required, and the JSON may include sensitive text. No verified structured-clone recovery/export exists.
- Existing browser-suite helpers (including `sc1-app.spec.cjs`) seed/read legacy keys directly or explicitly open version 1. They are not adapted by this follow-on and will fail or exercise the wrong store. Coordinate adaptation and run the entire suite before release; focused tests are not full-suite evidence. The old CAS unit model was replaced with JSON recovery checks; canonical CAS is now tested against real IndexedDB.
- The focused offline Chromium tests cover blocked upgrade, retained legacy and unrelated keys, old/new divergence, conflicting/stale writers and removal, Map/cycle/alias round trip, a detected graph split, injected upgrade abort/rollback, synthetic quota-like write failure and retry, unsupported load, and connection invalidation. They use fictional fixtures, not personal data or live AI. Injected errors do not prove behavior under actual quota exhaustion, storage eviction, power loss, every browser, or every migration race.

## Outstanding product quality risks

Independent fictional probes showed that a proposed rewrite can swap the percentages assigned to two outcomes without a guard note, while a supported `Prepared SQL` rewrite can be restored by an overbroad phrase check. These are isolated diagnostic cases, not production error rates. The comparison helps a person review but does not detect or correct these errors. PDF two-page whitespace and real-model quality remain open. No live model calls were made for this prototype.

## Browser regression status

Before the storage-isolation follow-on, the complete offline browser run on the earlier historical-review branch passed 96 of 98 cases; two old tests expected the comparison shortcut to disappear when the source was removed. A local test-only correction checked that the historical comparison remains accurately labeled and excludes later edits, and both cases passed individually. The corrected test file was not uploaded as part of the branch because it exceeds the connection's single-request size limit; the accompanying patch preserves the tested change. Do not treat the 96/98 run as a fully passing final suite. The full suite has not been rerun after applying that patch.

## Independent migration review

The independently reproduced in-flight save/version-change race was corrected locally, and its app-level regression passed after the fix. This does not resolve other release blockers: legacy writers can diverge without detection; valid Blob metadata can prevent startup; unrelated shared references can cause ordinary edits to be rejected; and backup/recovery is incomplete. Independent review found rollback and canonical compare-and-swap worked in the limited cases tested. The post-fix focused run passed 12 offline Chromium tests and one recovery test, and the build passed with dependency and chunk-size warnings. The complete unit and browser suites were not run on this follow-on; existing browser helpers still use the legacy store. Do not merge or use with important data.
